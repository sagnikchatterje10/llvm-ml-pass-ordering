1. Executive Summary: What We Convey Through the First 70%

Modern optimizing compilers such as LLVM/Clang rely on dozens of discrete transformation passes (e.g., dead code elimination, constant propagation, loop unrolling, instruction combining). Conventionally, software engineers invoke high-level compiler flags such as -O2 (optimizing for runtime speed) or -Oz (optimizing for minimal code size).

The Core Problem (Phase Ordering): Compilers use a single, hardcoded, one-size-fits-all pass sequence for every program. However, code transformations interact non-linearly: an optimization pass can create or destroy opportunities for subsequent passes. Consequently, a pass sequence that shrinks matrix multiplication can severely bloat an image convolution or a state-machine routine. Searching the entire space of pass permutations at compile time is computationally intractable (NP-hard).

The Core Project Thesis (70% Deliverable): By inspecting the static structural "DNA" of a program's LLVM Intermediate Representation (IR)—measuring instruction mix, control-flow branching, memory operations, and loop characteristics—a lightweight Machine Learning classifier can predict a custom, short optimization pass sequence tailored to that specific program. This predicted sequence outperforms LLVM's official -O2 and -Oz flags in code size under a strictly constrained compilation budget, with near-zero inference latency (17–45 ms).

Key Architectural Advantages Demonstrated:

  1. Zero Runtime Search Penalty: Unlike genetic algorithms that require re-compiling a program hundreds of times, our model makes a deterministic classification in under 45 milliseconds.
  2. Prevention of Destructive Optimizations: Standard -O2/-Oz flags frequently apply loop vectorization and unrolling heuristics that duplicate instructions. Our ML model identifies small loop bodies and selects minimalist simplification pipelines (e.g., simplifycfg, instcombine), eliminating 45.6% of binary bloat.
  3. Guaranteed Leakage-Free Evaluation: Unlike naive ML benchmarks that split rows randomly, we enforce strict program-level partitioning: training, validation, and testing share zero source files.

3. Practical Demonstrations: Step-by-Step System Walkthrough

The system is fully implemented and executable. The table below details what is demonstrated at each stage of the pipeline, the exact commands executed, and the physical outputs verified.

Step 1: Environment & Toolchain Diagnostics

python scripts/check_environment.py
  • What the Demonstration Shows: Verifies Python 3.12, scikit-learn, pandas, numpy, and autodetects the LLVM toolchain (Clang 23.1.2 and llvm-size). Generates experiments/environment_manifest.json.
  • Key Technical Innovation: Handles modern LLVM 23 architectures that omit standalone opt.exe by orchestrating optimization passes through Clang's internal pass manager and cross-platform header resolvers.

Step 2: Benchmark Suite & Zero-Leakage Dataset Splitting

cat benchmarks/metadata/manifest.json
  • What the Demonstration Shows: 40 diverse C benchmarks across 9 distinct algorithmic categories: arrays_loops, sorting, searching, recursion, arithmetic, bitwise_logic, string_processing, memory_structures, and control_flow.
  • Partitioning: 27 Train (67.5%), 6 Validation (15%), 7 Held-Out Test (17.5%). Programs are partitioned at the file level so test code is completely unseen.

Step 3: Automated LLVM IR Generation

python scripts/build_ir.py
  • What the Demonstration Shows: Compiles all 40 C files into clean LLVM Intermediate Representation (ir/*.ll).
  • Critical Implementation Requirement: Applies -Xclang -disable-O0-optnone. Without this flag, Clang tags functions with optnone, which silently prevents subsequent optimization passes from executing.

Step 4: Deterministic 30-Feature IR Extraction

python scripts/extract_features.py
  • What the Demonstration Shows: Parses the LLVM IR grammar and extracts 30 static numerical features across:
    • Program Size: Instruction count, basic block count, function count.
    • Control Flow: Unconditional/conditional branches, switches, branch-to-instruction ratio.
    • Memory: Load, store, alloca, getelementptr (GEP) counts and load/instruction ratios.
    • Computation: Integer/floating-point arithmetic, bitwise operators, comparisons.
    • SSA & Normalization: PHI nodes, select instructions, instructions per basic block.
  • Output: Generates features/ir_features.csv (40 rows × 30 deterministic feature columns).

Step 5: Candidate Pass Sequences & Limited-Budget Profiling

python scripts/run_experiments.py --split all --budget 30
  • What the Demonstration Shows: Evaluates 42 candidate pipelines (Baselines O2, OZ, and candidate sequences S01–S40) using safe optimization passes (instcombine, simplifycfg, sroa, dce, gvn, sccp, licm, mem2reg).
  • Budget Constraint: Limits sequence evaluations to at most 30 per program to avoid combinatorial explosion. Evaluates 1,280 compilations using 12 parallel threads with thread-safe disk caching in experiments/results_cache.json.

Step 6: Supervised Model Training & Feature Importance

python scripts/train_model.py --model all
  • What the Demonstration Shows: Merges features and empirical winning labels into dataset/dataset_train.csv and dataset_test.csv. Trains both a Random Forest Classifier and a HistGradientBoosting Classifier.
  • Results: Random Forest achieves 100% training accuracy and 57.1% top-3 test accuracy. Models are serialized to models/random_forest_pass_predictor.joblib.
